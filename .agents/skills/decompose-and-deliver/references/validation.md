# Behavioral validation and compatibility boundaries

Use safe fixtures and fresh-session evaluation when changing this workflow.
Give the evaluator a realistic request, the unchanged package and minimum raw
artifacts; do not disclose intended answers or previous conclusions. Check
observable decisions and generated artifacts against the original requirements.

| Scenario | Evidence to inspect |
| --- | --- |
| Trivial fix | One session/PR and ordinary gates; no unnecessary team or stack. |
| Independent changes | Verified isolated roots/branches/bases, bounded assignments and attributable returns. |
| Foundation then independent work | Shared owner establishes prerequisites before dependent dispatch. |
| Tightly coupled changes | Sequential execution, without inventing independence. |
| Worker clarification | Question and answer travel through the original coordinator only. |
| Material decision changes | Decision revision distributed; affected assignments revoked and evidence invalidated. |
| Missing isolation/delegation or one-PR runtime | Supported sequential/read-only fallback and explicit delivery limits. |
| Shared-resource contention | Explicit reservations/separation or serialized access. |
| Downstream overload | Unfinished-work limit includes CI/review/integration; prioritize completion. |
| Crash/replacement/late result | Stop/quarantine prior attempt; reconcile before accepting a superseded return. |
| Coordinator resumption | Reconcile tracker against actual Git, workers, remote PRs/reviews and CI. |
| Lower-stack edit or squash merge | Correct owning layer and recover descendants without duplicate patches; rerun checks. |
| Partial remote update or misleading exit | Inspect remote postconditions; recover without duplicate PRs or unguarded force. |
| Denial or worker direct-user attempt | Preserve permission boundaries and coordinator-only communication. |
| Edit after verification | Reject stale evidence and validate current integrated revision. |

## Portability test

Copy only the package into a separate safe repository with materially different
layout, commands, branch convention and instruction structure. Deny access to
initial-repository files where the test runtime supports filesystem isolation.
Resolve repository and package roots independently, including invocation from a
nested directory. Discover that target's actual commands and instructions. Change
its source layout and remove an optional tool; verify adaptation/fallback without
editing the package. Compare all copied package file hashes before and after.
Use local fixtures rather than remote test PRs or permission changes.

## Claims and evidence

Classify packaging/link checks as structural checks, deterministic script
execution as executed tests, and decisions over supplied crash/stack/remote
transcripts as simulations. Fresh-agent behavior is not proof that the actual
remote mutation, approval UI or recovery occurred. Record the installed runtime,
input revisions/package hashes, commands, outcomes and accessible reports in
the target's tracker/PR, outside this reusable package.

Current compatibility is documentation-supported for Codex, Copilot CLI,
VS Code and cloud discovery. Actual discovery, messaging, permissions, stack
mutation and queue behavior require runtime-specific evidence. Passing fixture
tests cannot establish cross-client execution or independent mergeability.
